# Content and maintenance

## Pages

| File | Edit by hand? | Notes |
| --- | --- | --- |
| `index.html` | Yes | Showcase page. Keep claims matching Porto's README. |
| `404.html` | Yes | Uses root-absolute links. |
| `assets/styles.css`, `assets/site.js` | Yes | Shared by every page. |
| `docs/*.html`, `sitemap.xml` | No | Generated by `node scripts/build.mjs`. |
| `vendor/porto/**` | No | Synced from Porto; checksums are verified. |

`index.html` and `404.html` contain `<!-- site:head -->`, `<!-- site:header -->`
and `<!-- site:footer -->` regions. The build replaces their contents from
`scripts/layout.mjs`, so the header, footer and metadata stay identical on every
page. Edit attributes on the opening comment, not the generated lines.

Run `node scripts/build.mjs` after editing any page, layout or script, and commit
the result. CI fails when generated files are stale.

## URLs

Pages stay `.html` files, but every link uses GitHub Pages clean URLs, which
serve `/docs/installation` from `docs/installation.html`:

- Link a page without the extension: `docs/installation`,
  `docs/installation#macos`, `../docs/runtimes`.
- Link a directory index with a trailing slash: `./`, `docs/`, `../`. Pages
  redirects `/docs` to `/docs/`, so never drop the slash.
- Keep links relative in `index.html` and generated pages; `404.html` uses
  root-absolute links such as `/docs/`.
- Canonical, `og:url` and `sitemap.xml` URLs follow the same form:
  `https://porto.synctune.it/docs/installation`, `https://porto.synctune.it/docs/`.

`scripts/layout.mjs` writes the shared links, and `resolver()` in
`scripts/build.mjs` maps Markdown links between Porto documents to these URLs.
`scripts/check-links.mjs` resolves `a` to `a.html` and `dir/` to
`dir/index.html`. It fails on links ending in `.html`, on links to a directory
without the trailing slash and on targets that do not exist. Old `.html` URLs
still load on GitHub Pages, so inbound links keep working.

## Update the Porto documentation

The docs are a snapshot of one Porto commit, recorded in
`vendor/porto/SOURCE.json` (`ref`, `commit`, `version` and a SHA-256 per file).
Sync a newer release tag:

```sh
node scripts/sync-porto.mjs --ref v1.12.0
node scripts/build.mjs
node --test tests/ && node scripts/package.mjs dist && node scripts/check-links.mjs dist --external
```

Without `--source`, the script shallow-clones the tag from GitHub. Pass
`--source /path/to/porto` to read from an existing checkout instead (read-only
Git commands). The sync:

- Fails when `docs/` gains a Markdown file that `scripts/pages.mjs` does not
  publish. Add it to a section with a title, slug and short summary.
- Resolves every relative link. Links to published documents become site links;
  links to other repository files become GitHub URLs pinned to the synced
  commit. Missing targets fail the sync.
- Keeps `assets` and `derived` provenance entries from the previous manifest.
  It warns about remote images that are not vendored; those render as links.

Never edit files under `vendor/porto`. Fix wording or links in Porto itself,
release it, then sync. Known upstream outbound failures live in
`knownUnreachable` in `scripts/check-links.mjs`; remove an entry once Porto
fixes the link.

## Markdown rendering

`scripts/markdown.mjs` is a small GitHub-flavored Markdown renderer with no
dependencies. It covers what Porto's docs use: ATX headings with GitHub-style
ids, paragraphs, flat lists with continuation lines and nested code, fenced code,
tables, block quotes, GitHub alerts, links, images, emphasis, autolinks, front
matter and simple Mermaid flowcharts (rendered as an accessible list). Raw HTML
is escaped, except `<img>` blocks, `<br>` and comments.

When upstream docs start using new syntax, extend the renderer with a focused
test in `tests/site.test.mjs`. The link check catches anchors whose ids no
longer match GitHub's.

## Brand and images

`vendor/porto/SOURCE.json` records the origin and checksum of each image:

- `assets/favicon.svg` is an unmodified copy of Porto's `ui/public/favicon.svg`,
  the same mark as the macOS Icon Composer app icon.
- `assets/apple-touch-icon.png` is that icon's 1024 px PNG resized to 180 px.
- `assets/screenshots/dashboard.webp` is the README dashboard screenshot at its
  1728 x 1117 display size. `assets/social.png` is a 1200 x 630 crop of it.

Colors and type follow Porto's design system (`docs/design.html`): neutral
graphite surfaces, the olive, amber and fault-red signals, system UI fonts and
dark instrument surfaces (header, code, diagrams) in both themes. Do not add
web fonts, brand hues or third-party assets.

## Before publishing a change

- Keep copy truthful to the pinned Porto release. Do not invent metrics,
  testimonials, release dates or screenshots.
- Check narrow (320 px) and wide screens in dark and light schemes, keyboard
  focus and the skip link. Pages must keep one `h1`, a `main` landmark and
  alternative text for images.
- The Content-Security-Policy only allows same-origin resources and no inline
  scripts or styles. Keep styles in `assets/styles.css`.
- Keep `CNAME`, canonical URLs, `robots.txt` and `sitemap.xml` on
  `porto.synctune.it`.
